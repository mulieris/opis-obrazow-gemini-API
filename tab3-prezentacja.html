idea

Idea po co to jest

Zakładka Tab3 pozwala użytkownikowi przesłać zdjęcie oraz wpisać instrukcję tekstową (np. „Jaki to owoc i jakiego koloru?"). Aplikacja wysyła obraz + instrukcję do modelu Gemini, a ten zwraca opis treści obrazu zgodny z instrukcją.

Wejście

Obraz (PNG/JPEG) + instrukcja tekstowa od użytkownika.

Przetwarzanie

Gemini analizuje obraz w kontekście instrukcji i tworzy opis.

Wyjście

JSON { found, answer } → opis pokazany w powiadomieniu.

frontend

Frontend — Tab3.java co kształtuje widok

Layout poziomy: po lewej karta z formularzem, po prawej podgląd zdjęcia. Przycisk jest aktywny dopiero gdy jest plik i tekst.

// kliknięcie „Opisz" — wyślij obraz + instrukcję, pokaż wynik
buttonPhotoChange.addClickListener(event -> {
    String text  = textFieldChange.getValue();
    byte[] image = memoryBufferChange.getInputStream().readAllBytes();
    WebService ws = ApplicationContext.getBean(WebService.class);
    PhotoToChange result = ws.isValidChange(text, image);

    String message = result.isFound()
            ? result.getAnswer()
            : "To nie jest coś co mogę opisać.";
    new Notification(message, 15000).open();
});

Podgląd: po udanym uploadzie bajty pliku trafiają do StreamResource, ustawianego jako src komponentu Image (550×550).

backend

Backend — prompt do Gemini photoChange()

Obraz kodowany jest do base64 i wysyłany razem z instrukcją jako inline_data. Prompt wymusza odpowiedź w formacie JSON.

String base64Image = Base64.getEncoder().encodeToString(image);
jsonPayload = """
  { "contents":[{ "parts":[
    { "text":"Opisz zawartość obrazu zgodnie z tą instrukcją: %s.\n
               Zwróć odpowiedź wyłącznie w formacie JSON:
               { \"found\":true/false, \"answer\":\"opis\" } ..." },
    { "inline_data":{ "mime_type":"image/jpeg", "data":"%s" } }
  ]}] }""".formatted(text, base64Image);

// odpowiedź → GeminiParser.parsePhotoResponse() → PhotoChangeResponse

Komunikacja z Gemini przez java.net.http.HttpClient; model gemini-2.5-flash (multimodalny).

bug-report

Stan zastany dlaczego nie działało

Po złożeniu kodu zakładka „nic nie robiła". Diagnoza wykazała kilka błędów, które blokowały kompilację i działanie backendu:

  • Backend się nie kompilował — pomieszane klasy i metody.
  • Brak endpointów /photo i /plate — żądania frontu trafiały w 404.
  • Niepoprawny JSON w promptcie (surowe znaki nowej linii).
  • Złe nazwy akcesorów — dane nie wiązały się z JSON-em.
  • Brak getterów w ImageResponse → błąd 406.
  • Puste catch {} — błędy ukryte, brak jakiejkolwiek informacji.
  • Backend nie był uruchomiony — front pukał na pusty port 8081.

root-cause

Diagnoza „kliknięcie nic nie robi" dlaczego naprawdę

Po naprawie kompilacji zakładka nadal nie reagowała. Sprawdzenie portów ujawniło prawdziwą przyczynę:

frontend :8080  -> 200   // działał
backend  :8081  -> 000   // connection refused — NIE był uruchomiony!

Frontend tylko przekazuje żądanie do backendu (port 8081), a ten dopiero rozmawia z Gemini. Bez uruchomionego backendu przycisk „Opisz" zawsze kończył się błędem.

→ Po uruchomieniu backendu wszystkie 3 endpointy zwracają 200, a zakładki działają end-to-end.
